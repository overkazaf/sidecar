1. 什么是 sidecar

sidecar 在标准 Linux 机器上启动一个基于 Android 的音频处理二进制。它利用 Linux 内核命名空间创建隔离环境（沙箱），使 Android 二进制认为自己运行在真实设备上——但宿主系统不会被修改，也不需要 root 权限。

可以这样理解：Apple Music 以需要特殊处理的格式传输音频。这种处理在 Android 运行时内执行。sidecar 的工作是安全地搭建这个运行时、监控它、并在崩溃时重启——一切只用一个 35KB 的二进制文件。

无需 root

使用 Linux 用户命名空间创建隔离环境，无需任何超级用户权限。

无需 Docker

35 KB 原生二进制。无需容器运行时、镜像仓库或守护进程。编译即可运行。

可观测

PTY 输出转发实时展示子进程的运行状态。JSON 事件用于监控集成。

自愈

检测端口就绪状态，通过 SIGUSR1 在崩溃后重启，支持可配置的优雅退出等待。

3. 进程隔离 Model

sidecar 使用 Linux 用户命名空间——与无 root 容器相同的内核机制。关键点：在用户命名空间内，普通用户（uid 1000）被映射为 root（uid 0）。这提供了 chroot() 等能力而无需真正的 root 权限。

9. 常见问题

sidecar 到底做了什么？（简单解释）

可以把它想象成一个翻译环境搭建工具。Apple Music 以需要特殊处理的格式传输音频。这种处理在 Android 二进制中运行。sidecar 为该二进制创建一个安全的隔离空间——就像一个沙箱。你的电脑不会被修改，也不需要管理员权限。

为什么不直接用 Docker？

Docker 可以用，但对这个场景来说太重了。Docker 容器需要守护进程、200-500 MB 的镜像、3-5 秒启动时间和约 150-200 MB 内存。sidecar 用 35 KB 二进制、2.1 秒启动和 52 MB 内存完成同样的工作。它使用与 Docker 相同的内核机制（命名空间），但没有那些开销。

安全吗？会修改我的系统吗？

sidecar 使用 Linux 用户命名空间——进程认为自己是 root，但实际上以你的普通用户身份运行。它无法修改 rootfs 目录之外的文件，无法访问其他进程，也无法更改系统设置。sidecar 退出时一切都会被清理。

如果子进程崩溃了怎么办？

sidecar 检测到崩溃后会自动重新 fork 子进程。发送 SIGUSR1 触发优雅重启。sidecar 进程本身保持存活——PID 不会改变，这对 systemd 等进程管理器很重要。
