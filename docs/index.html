⚙ Architecture

sidecar creates an isolated Linux user namespace, bind-mounts the host kernel interfaces into an Android rootfs, and execs the FairPlay binary inside the chroot. The child exposes two raw TCP ports for pipelined decrypt and HLS resolution.

sidecar (PID 1, user space) │ ├─ unshare(CLONE_NEWUSER | CLONE_NEWNS) │ ├─ write /proc/self/uid_map → 0 <real_uid> 1 │ └─ write /proc/self/gid_map → 0 <real_gid> 1 │ ├─ bind-mount /dev, /proc, /sys → rootfs/ ├─ seed /etc/{resolv.conf, hosts} → rootfs/etc/ │ ├─ chroot("./rootfs") │ └─ exec /system/bin/main (FairPlay daemon) │ ├─ TCP :47010 — decrypt (sample-by-sample stream cipher) │ └─ TCP :47020 — m3u8 (HLS master URL resolution) │ └─ supervisor loop ├─ PTY drain (line-buffered child output) ├─ port readiness gate (--wait-ports) ├─ SIGUSR1 → graceful restart (re-fork, no PID change) └─ SIGTERM → grace shutdown (TERM → wait → KILL)

⚡ Why sidecar

The community has built impressive tools for Apple Music ALAC decryption. sidecar builds on that foundation while solving real operational pain points:

No Root Required

User namespace isolation (unshare) maps your UID to root inside the namespace. No sudo, no capabilities, no Docker daemon.

Full Observability

PTY-forwarded child output (line-buffered, not swallowed). --json-events for machine-parseable status. --verbose for human-readable progress.

Port Readiness Gate

--wait-ports 47010,47020 blocks until the decrypt daemon is actually listening. No blind sleep/poll needed.

Graceful Lifecycle

SIGUSR1 re-forks the child without restarting sidecar itself. SIGTERM sends graceful shutdown with configurable timeout.

DNS Bootstrap

Automatically seeds resolv.conf, hosts, and nsswitch.conf into the chroot. No silent DNS failures.

Single C File

923 lines, zero dependencies beyond libc + libutil. Build with make. Audit the entire codebase in an afternoon.

🚀 Quick Start

Build

# Clone and build
git clone https://github.com/overkazaf/sidecar.git
cd sidecar
make          # → ./sidecar (39 KB)

Run (code-from-file mode, no login)

./sidecar --userns --rootfs ./rootfs --bin /system/bin/main \
  --wait-ports 47010,47020 --verbose \
  -- -M 47020 -D 47010 -F

Run (login mode, first-time auth)

./sidecar --userns --rootfs ./rootfs --bin /system/bin/main \
  --wait-ports 47010,47020 --verbose \
  -- -M 47020 -D 47010 --login=user@host:pass

Multi-instance (4 parallel decrypt workers)

for i in 0 1 2 3; do
  ./sidecar --userns --rootfs ./rootfs --bin /system/bin/main \
    --wait-ports $((47010+i)),$((47020+i)) \
    -- -M $((47020+i)) -D $((47010+i)) -F &
done

Graceful restart (re-login without restarting sidecar)

kill -USR1 $(pgrep -f sidecar)

🔌 Wire Protocol

The FairPlay binary exposes two raw TCP ports. Both are locally-unauthenticated with simple length-prefixed binary framing.

Port 47020 — m3u8 (get-stream)

Resolves an Apple Music adamId to an enhanced-HLS master playlist URL.

client → server:  0a 31 34 34 30 38 34 31 32 36 33
                  └─┘ └────── '1440841263' ──────┘
                  len

server → client:  "https://aod-ssl.itunes.apple.com/...master.m3u8\n"

Port 47010 — decrypt (sample-by-sample)

Full-duplex pipelined stream cipher. Supports multiple key contexts per connection.

# Key context header (once per key):
len(adamId) adamId len(keyUri) keyUri

# Per-sample (repeated):
LE-uint32 sample_len ciphertext[sample_len]  →  plaintext[sample_len]

# End context:
00 00 00 00

🔗 Integration with aria

aria is the HTTP API service that orchestrates the full ALAC pipeline: Apple catalog lookup → HLS download → FairPlay decrypt via sidecar → m4a output. 

# aria_sidecar.py manages N sidecar instances
python3 aria_sidecar.py -F --instances 4

# aria server round-robins decrypt requests across instances
ARIA_INSTANCES=4 python3 server.py --port 8899

# Download Hi-Res ALAC
curl -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8899/download/1440841263?fmt=alac" \
  -o song.m4a

The DecryptPool in aria's decryptor.py maintains one TCP session per sidecar instance with per-instance mutex locks, ensuring each decrypt daemon handles one track at a time.
